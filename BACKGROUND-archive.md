## Background (moved from CLAUDE.md)

### libm exactness
- The `libm` crate (musl) `log` ≠ `StrictMath.log` (1 ulp in ~1% of inputs, seen in `nextGaussian`). Use ported fdlibm (`src/fdlibm.rs`) for StrictMath semantics.
- RWG2 uses `Math.*`, not `StrictMath`. HotSpot intrinsifies `Math.sin/cos/log/pow` on x86_64/aarch64, and the results can differ from fdlibm. This only affects the terrain gates (volcano/lava-cave). Validate against the pack oracle; if the intrinsics differ, port the intrinsic algorithm or accept and flag it.

### RWG2 internals (`src/main/java/rwg2/`)
- `world/ChunkManagerRealistic.java` (~1074 lines) — biome provider.
  - `public ChunkManagerRealistic(long seed, boolean continental)` → **no World required**.
  - Biome size from `ConfigRWG.biomeSizeMultiplier` (climateWidth 1400×, biomeWidth 500×).
  - Pure noise; **no GenLayer stack**. Climate cells + warp, `CellNoise`, `PoissonPointNoise` (small biomes, seed ^ 0x510E527FADE682D1, spacing 1020), `ContinentalNoise` (continents only, seed ^ 0x6A09E667F3BCC909), climateWarp (seed ^ 0xBB67AE8584CAA73B).
  - Key methods: `getBiomeDataAt(x,z)`, `getBiomeGenAt`, `getBiomesGens(x,z,w,h)`, `getNoiseAt(x,z)` (terrain height), `getContinentValue`, `getOceanValue`, volcano / lava-cave coordinate helpers.
  - Biome candidate lists = hardcoded RWG biomes + `Support.*` lists (populated at mod init from `support/SupportBOP`, `SupportEBXL`, `SupportTC`, `SupportCC`), filtered by config. **List order matters** (selection indexes into them). Categories: snow/cold/hot/wet/small/test + border/coldBorder/hotBorder/veryCold/veryHot/littoral/small/island/smallIsland/largeIsland.
- `util/NoiseSelector.java`: noise impl chosen from per-world `RwgWorldSavedData` (`rwg_data`, key `noiseImplementation`): UNKNOWN/DYNAMICPERLIN → `NoiseGeneratorWrapper` (perlin), PERLIN, OPENSIMPLEX, DYNAMICOPENSIMPLEX.
  - ⇒ Inputs are **(seed, worldtype, noiseImplementation)**, not just seed. **Resolved:** nothing calls `setNoiseImplementation` except `/rwg_noise` (`RwgNoiseCommand`); the detection in `LoginHandler` is commented out. New worlds stay `UNKNOWN` → `NoiseGeneratorWrapper` with `useOpenSimplex=false` → **plain PerlinNoise**. OpenSimplex only matters for worlds where an admin ran `/rwg_noise`.
  - Sets static `NoiseGeneratorWrapper.useOpenSimplex` → global state, unsafe to mix impls across threads in one JVM.
- `world/ChunkGeneratorRealistic.java` (~1173 lines) — chunk gen.

### Biome path findings (read 2026-11-02, RWG2 @ `3b49c7e`, pinned in `oracle/RWG2_COMMIT`)
- **In CONTINENTS mode the biome map depends on terrain height.** Two gates:
  - Volcano island biome: `getVolcanoCoordinates` → `canGenerateVolcanoAt` → `!hasRiverNearVolcano` (cell-noise river field, cheap) **and** `RealisticBiomeIslandVolcano.canGenerateAtHeight(getVolcanoBaseHeight)` → `biome.rNoise(...)` + `calculateRiver` at the volcano center.
  - Lava-cave marker biome (`getBiomeGenAt` only, not `getBiomeDataAt`): `canGenerateLavaCaveAt` → `getNoiseAt(center) > 63f` → `rNoise` of whatever biome sits at the cave center.
  - ⇒ "biomes first, heights later" doesn't fully work. Port order: biome selection first (exact everywhere except the two landmark gates), then the `rNoise` for every biome (`terrain/` is 20 classes / ~750 lines + per-biome glue), then the gates.
- Math on the **biome selection path**: only `sqrt`, `floor`, `ceil`, `round`, `abs`, `min`/`max`, all exact in IEEE, plus `java.util.Random`. No transcendentals ⇒ exactness is very achievable.
- Transcendentals elsewhere: `TerrainMath` (`Math.sin/cos`, terrain), `LavaCaveLandmark` (`Math.pow`, chunk gen only), Perlin `bias/gain` (dead code).
- Noise classes (`PerlinNoise`, `CellNoise`, `PoissonPointNoise`, `ContinentalNoise`, `IslandPointNoise`, `ContinentLandmarkNoise`) are standalone Java (Trove maps are caches only; `ConfigRWG` statics) ⇒ the oracle can compile them **verbatim** with tiny shims, no Forge.
- Biome lists (`Support.*`) depend on loaded mods + their configs/IDs ⇒ these need one export from a real GTNH 2.9 instance (dump mod / command). Everything else can be oracled standalone.
- `getBiomesToSpawnIn()` returns an empty list and `findBiomePosition` returns null ⇒ vanilla spawn starts at (0,0) and random-walks on `canCoordinateBeSpawn` — BOP's version in GTNH (sand/stone top), see Spawn.
- `getBiomeDataAt` caches in a 4096-entry Trove map cleared on overflow. It's pure, so the cache can be ignored.

## Surface blocks (v1.43, 2026-11-08)
- Ground truth: rwg2dump `worldchunks` stores only the top block name (no metadata, no filler) → stained clay colours, red vs plain sand, coarse dirt / podzol and filler layers are unverified (ported from source).
- Painting biome = `Chunk.rwg`; RWG2 calls `rReplace(blocks, …, blockX, blockY, i, j, …)` → paint `i, j` = world x, z; column loops k 255→0, air resets depth, water skipped (Ocean: water resets), Support runs each surface with depth −1.
- Cave `digBlock` (Forge 1.7.10): digs stone / provider top / filler (exception biomes desert, beach, mushroom = grass/dirt), y < 10 → lava, `foundTop` turns the filler below into the top. Which painted layers dig still comes from the fitted `hard_layers` (spawn.rs); only the filler → top fix uses the provider table.
- Not modelled: population (trees, plants, lakes, boulders, GT surface ores), Hot Plains river-oasis cave columns (16 misses, unexplained).

Only if score < 0.59; columns at chunk origin + 8 (so column x is decided by chunk (x−8)>>4); skip if gen temp ≥ 0.15; s = −1 if score < −0.59 else perlin(x/3, z/3) + score; s < 0 → water at precip height − 1 becomes ice, else snow layer if below is opaque (not ice / packed ice / water / lava / snow / air) and y > 62. Precip height ignores snow layers. Small residual (5 FP / 738) unexplained, likely trees/plants removed from the opaque test.
- TF caves: digging a grass block sets `hitGrass`; lining (dd ≥ 0.85) becomes grass if set else stone (highlands) / dirt, then resets; if set and the block below is dirt it becomes the biome top. Remaining TF top misses are all grass→dirt.
- Nether surface: 136 Corrupted Sands soul sand, 137 Phantasmagoric Inferno ash, 117 Visceral Heap flesh, 94 Polar Chasm hard ice, 138 Undergarden overgrown netherrack top over netherrack; flag1 → gravel, flag → soul sand. ✅ rwg2dump 2.15.1: every block of 7×7 chunks exact (v1.48).

## Wasm SIMD experiment (2026-11-09, not shipped)
- `tools/bench-wasm.mjs [wasm]`: biome / terrain / blocks tiles, an ores + Thaumcraft cell and two searches, with an FNV digest of all outputs (two builds are equivalent iff digests match; run each 2–3×, ±10% run noise).
- V8 cpu profile of that bench (scalar build): Perlin `noise2` 21% (not inlined), `ChunkGen::generate` 7.5%, `CellNoise::noise` 5.5%, `Caves::tunnel` 5.5%, landform 4.9%, landmark 4.6%, island 3.8%, Poisson ~12% over 4 functions; the rest < 3% each. rustc 1.97 already enables nontrapping-fptoint / bulk-memory / sign-ext on wasm32.
- `+simd128` autovectorisation: same digest, no speed change. Hand-vectorised `noise2` (one point, 4 dot products in f32x4 lanes): bit-exact, ~15% slower (lane packing > saved multiplies). Force-inlining `noise2`: no change, +140 KB. Batched `noise2_x4` (4 independent points, scalar gathers, f32x4 arithmetic): bit-exact, ~1.5× per call (1.3–2.4×, wasmtime) → ceiling ~7% overall, and it needs the octave sums of all 19 terrain formulas restructured into 4-point batches plus a second wasm build with feature detection. Dropped: the code is gather-bound, not arithmetic-bound.
