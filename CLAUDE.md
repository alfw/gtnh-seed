# GTNH Seed Viewer — project handoff

Online seed/biome viewer + seed search for **GT New Horizons** (MC 1.7.10, Forge). Like mcseedmap/chunkbase, but for GTNH's modded worldgen.

Owner stack: Rust (backend/tooling), Svelte (frontend), Node where needed.

## Ground truth (verified by reading source, 2026-11-02)

### Which worldgen GTNH uses
- **Not RTG.** GTNH ships **Realistic-World-Gen** (ted80 RWG fork, `GTNewHorizons/Realistic-World-Gen`, alpha-1.5.3 in 2.9) → "RWG1", used by pre-2.9 worlds.
- **GTNH 2.9.0** (released 2026-10-31) adds new mod **Realistic-World-Gen-2** (`GTNewHorizons/Realistic-World-Gen-2`, 2.0.6). World types registered in `RWG.java`:
  - `RWG2` → `new WorldTypeRealistic("RWG2", false)`
  - `RWG2_CONTINENTS` → `new WorldTypeRealistic("RWG2_CONTINENTS", true)`
- 2.9 release notes: upgraded worlds keep original worldgen (no chunk seams).
- **Decision (2026-11-02): RWG2 only. No RWG1 support**: no seed finder for pre-2.9 worlds, since 2.9 ships RWG2 as the default. Both RWG2 world types are supported (`RWG2_CONTINENTS` is primary; plain `RWG2` comes almost free).
- `DefaultWorldGenerator` (client-side mod, 0.5.0 in 2.9) picks the default world type. **Resolved:** pack `config/defaultworldgenerator.cfg` → `World Generator=RWG2_CONTINENTS`, whitelist `flat, RWG, RWG2_CONTINENTS` (plain `RWG2` is *not* selectable without Alt-cycling). ⇒ Primary world type: **RWG2_CONTINENTS**.
- Pack ships **no `config/rwg2.cfg`** (the `RWG.cfg` in the pack is RWG1's) → RWG2 runs on `ConfigRWG` code defaults: `biomeSizeMultiplier=1`, all landmass/biome offsets 0, etc. Re-check per pack release.
- People hunt 2.9 seeds for **biomes**, not just ore veins.

### Chunk generation (`ChunkGeneratorRealistic`) — ported as `chunkgen.rs`
- **Real terrain ≠ `getNoiseAt`.** `provideChunk` → `getNewNoise`: 21×21 `getBiomeDataAt` samples at 8-block spacing (volcano island → `getVolcanoUnderlyingBiome`), 17×17 parabolic weights at a 5×5 coarse grid, mix4 passes (HUGE 1 → HUGE 2 into smallRender → SMALL 1..4), per column `Σ rNoise(…, border = weight, river + 1) · weight` in ascending RWG id order, then volcano `rNoiseAt` override, lava-cave `surfaceHeight`, `calculateRiver`, mountain-chain fade. Column is stone up to `(int) testHeight`, water to 62.
- **The chunk biome array (F3 / Forestry / Thaumcraft / Roguelike) is dithered**: `biomesForGeneration` is a pick over the blended weights with `bRand = 0.5 + perlin(x/15, z/15)` (or the main biome if centre weight > 0.95), then volcano surface override, then `markLavaCaveOpeningBiome`. ~12% of columns near spawn differ from `getBiomeDataAt`. The map at step 1 renders this; zoomed out it renders the provider biome.
- ✅ **Validated:** 1.64M columns (9 regions, both types, incl. lava-cave surface), height bits + biome **0 mismatches**; world chunks 36,864 biome-array columns 0 mismatches; real top block == `(int) height` in 99.2% (rest = caves/carving). Cost ~1.2 ms/chunk native.

- Forestry 4.11.40 GTNH: `EnumTemperature.getFromBiome(b, x, y, z)` = HELLISH if BiomeDictionary NETHER, else thresholds (>1 hot, >0.85 warm, >0.35 normal, >0 cold, else icy) on `getFloatTemperature`; humidity from `rainfall` (>0.85 damp, ≥0.3 normal, else arid). Bee houses use the block position.

### GregTech ore veins (`gtores.rs`, GT5-Unofficial 5.09.54.265, 2026-11-03)
- Live vein list from rwg2dump 2.4 → `data/gtnh-2.9.0/gregtech.json` (21 overworld stone veins in `WorldgenGTOreLayer.sList` order, weights, Y, size, density, primary id, ore ids). Config: `oreveinPercentage` 100, attempts 64, max placement attempts 8, pattern EQUAL_SPACING (saved).
- Oreseeds: chunk with `floorMod(c, 3) == 1` on both axes. `oreveinSeed = (seed<<16) ^ ((dim&0xff)<<56 | (ox&0xfffffff)<<28 | (oz&0xfffffff))`; `XSTR(ovs).nextInt(100) < pct`; attempt i: `s = fnv1a64(fnv1a64(OFFSET, ovs), i)` (GTNHLib, sign-extended bytes), weighted `findRandom` with XSTR(s); `placement = fnv(s, primaryId)` → `veinMinY = minY + nextInt(maxY−minY−5)`, west/east (`nextInt(size)`), north/south. No overlap with the vein → ≥5 of 9 stone blocks at (chunkX+7, minY..minY+8, chunkZ+9) = NO_OVERLAP (accepted!); overlap → dry-run of the layer generator (any ore placeable in stone). Failure → next attempt (max 8 failures). Caves/ravines also matter. Model: terrain top at the vein-box centre ≥ minY+4 (wasm uses `noise_at`).

### GT ore order model (`gtorder.rs`, 2026-11-03)
- GT's task queue is FIFO and `MAX_VEIN_SIZE` = 2, so each oreseed is decided by the first populated chunk in its 5×5 window. Only `NO_OVERLAP_AIR_BLOCK` counts toward the 8 failures; the dry run keeps drawing from the placement RNG (`candidate_rng`); another material's ore is not stone.

## Decision (2026-11-02): WASM route first
Go straight to the Rust→WASM port; no production JVM tile server. The JVM is kept **only as a test oracle**:
- **Standalone oracle** (`oracle/`, in this repo): compiles verbatim RWG2 `util/` classes (+ later `ChunkManagerRealistic` with shims and synthetic biome lists) and emits golden vectors to `testdata/golden/`. Runs anywhere with a JDK.
- **Pack oracle** (later): a small dump mod or command in a real GTNH 2.9 instance that exports the biome-list JSON and golden biome grids for N seeds. It's the only way to validate `Support.*` list order and the `Math.*` intrinsics on the terrain gates.
