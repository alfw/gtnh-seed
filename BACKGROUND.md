## Trees step 1: decoration replay feasibility (2026-11-09, `deco.rs`, not in the viewer)
- RWG2 `populate` after the modelled prefix: Decorate SAND/CLAY/SAND_PASS2/TREE/BIG_SHROOM events (no draws in GTNH), then the border loop: every biome with border strength > 0 in ascending rwg id runs `rDecorate` on the shared Random (oceans deferred to after ICE; `RealisticBiomeSupport` runs its BOP / vanilla `BiomeDecorator` only above 0.3, its edits always). Each chunk reseeds the Random, so errors don't carry across chunks except through blocks a neighbour already placed.
- First decorating biome per chunk (43,200 chunks, 3 seeds): RWG2 native 64.7%, BOP decorator 35.2%. Natives' generators (`Deco*` trees, shrubs, blobs, cacti, flowers, grass; vanilla shrub / reed / pumpkin / dead bush) draw a fixed number of times once their world checks pass (ground block, air, water next to it, heightmap), so they replay on an exact block world.
- `deco::DecoWorld`: exact `surface_chunk` columns + prefix changes (`PopModel::last_deco_start` = Random + log length at the loop) + writes, heightmap updated like `Chunk.setBlock` (light opacity > 0). Ported: Stone Mountains Cactus, Canyon + their generators. Block identity matters: `Blocks.sand` includes red sand, `Blocks.dirt` coarse dirt / podzol (fixing this took the PoC from 0.49 to 0.73).
- ✅ PoC vs rwg2dump 2.15.1 red area (−27, 21), 28 of 49 chunks modelled (20 need BOP Prairie, 1 prefix unknown), every decoration block at its exact position, y 50–199: recall 0.731, precision 0.728 (`tests/tree215.rs` `deco_poc_215`, ignored; `PER_CHUNK=1`, `DBG_CHUNK=x,z` traces). Boulders 225/225 + 22/22, cacti 79/117, shrub leaves 775/934. Chunks away from unmodelled BOP neighbours are mostly 90–100%; the bad ones border Prairie chunks (their foliage changes the air checks; `leaves2:8` 80 real-only blocks are Prairie trees).
- Load order: the game populates (a, b) once (a+1, b+1), (a+1, b), (a, b+1) exist; generators with many conditional attempts (cacti 10 per call, grass 128, flowers 64) reach ±7 blocks into neighbour areas, so an unknown neighbour order desyncs them. Only 35 of the red area's 81 chunks were fresh when the dump ran.

## Populate order and the decoration ceiling (v1.59, 2026-11-09)

- **Order sensitivity** (dump 2.16, recorded order = z-major force-load = `canonical`; `deco_dump` env `DECO_XMAJOR=1` adds x-major / x-rev / z-rev, `DECO_SHUFFLE=n` random permutations, `DECO_GROUPS=4` the viewer's independent 4×4-group replays). Forward orders (each chunk after its −x / −z neighbours) differ little: x-major vs z-major Jungle 0.939/0.979 vs 0.939/0.980, Tundra 0.913/0.889 vs 0.940/0.936, Eucalyptus 0.626/0.805 vs 0.663/0.798. - **Run-vs-run ceiling** (`tools/deco_run_vs_run.py`): rwg2dump 2.17.0 full run on a second fresh world of seed 1631302684446519836 (`dump216b/`, 2026-11-09) vs `dump216/`; decoration recall / precision of run 2 against run 1: Garden 0.628/0.619, Eucalyptus 0.649/0.618, Fungi 0.547/0.627, Sunflower Plains 0.704/0.688, Temperate Forest 0.915/0.831, Tundra 0.936/0.959, Chaparral 0.960/0.998, Taiga 0.980/0.982, Jungle 0.999/0.999, Prairie 0.999/0.993, Frost Forest, Ice Plains Spikes, **Kelp Forest and Coral Reef 1.000 (oceans every voxel identical)**. ⇒ the `Math.random` biomes (Garden, Eucalyptus, Fungi, Sunflower, Temperate Forest) are at the ceiling; real headroom: Kelp Forest (model 0.11) and Coral Reef (0.51), deterministic, so the ocean reseed listener is deterministic (rwg2dump 2.18 probe), then Jungle, Frost Forest, Chaparral precision.
